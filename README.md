# Kingdom Helm chart and compiler

`charts/kingdom-workload` renders a standard Kubernetes Deployment and optional Service from application Helm values. Products declare their PodSpec in GitOps; this chart is shared and knows no product or environment names.

The build-time adapter in `ops/shadow/` consumes pinned Kubernetes manifests and provisional Compose generated by pinned dekube. It verifies the secret-volume, persistent-volume, resource, health and security semantics, then produces the checked Compose/runtime tree. The optional golden Compose comparison is declared by each application, not hardcoded here.

Helm, dekube and the compiler run **on the GitHub Actions runner**, never on the Docker VPS. ConfigMaps are included as read-only runtime files; Kubernetes Secret references become read-only host secret mounts. Secret **values** are delivered separately as an encrypted OCI via the central Kingdom pipeline.

For the complete application-facing interface and prerequisites, see [`kingdom-environments/AGENTS.md`](https://github.com/dmitrichcom/kingdom-environments/blob/main/AGENTS.md). Compiler invariants are described in [`ops/shadow/README.md`](ops/shadow/README.md). Quality gates: `qgate run`.
